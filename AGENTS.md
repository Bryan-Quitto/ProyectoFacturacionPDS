# MASTER RULES & GOVERNANCE: POINT OF SALE SYSTEM (POS)

## 1. CORE STACK & RUNTIME
- **Backend:** .NET 10 (C#) | EF Core | Classic ASP.NET Core Web API Controllers.
- **Frontend:** React 19 | Vite | Tailwind CSS | SWR | Orval (native `fetch`).
- **Database:** Supabase (PostgreSQL). Migrations via EF Core CLI exclusively.
- **PDF Engine:** QuestPDF on backend.

## 2. STRICT ARCHITECTURAL BOUNDARIES (REQ. 20, 21)
VERTICAL SLICES, MINIMAL APIS AND FASTENDPOINTS ARE FORBIDDEN. The backend must strictly follow a 4-tier N-Layer architecture:
- `POS.Domain`: Pure business entities, enums, domain exceptions. Zero external dependencies.
- `POS.Application`: Service interfaces/implementations (`ICustomerService`, `ISaleOrderService`, etc.), immutable Records (DTOs), tax calculation, Ecuadorian ID validator.
- `POS.Infrastructure`: `ApplicationDbContext`, EF Core Fluent API mappings, migrations, QuestPDF implementation.
- `POS.Api`: Controllers inheriting from `ControllerBase` under `/api/v1/`, global RFC 7807 middleware, JWT authentication, OpenAPI.

## 3. STRICT DUAL-LANGUAGE RULE (REQ. 16)
- **Backend (100% English):** All source code, class names, methods, variables, DTOs, database tables, columns, routes, and git commits.
- **Frontend & PDF (100% Spanish):** All UI labels, placeholders, buttons, validation errors, toast notifications, and generated invoice labels.

## 4. CONCURRENCY & TRANSACTIONAL RULES (REQ. 7, 8, 9, 17)
- **ACID Transactions:** Every sale order persistence and inventory deduction must be wrapped in an `IDbContextTransaction`.
- **Optimistic Concurrency:** `Product` entity must map PostgreSQL's system column `xmin` as a concurrency token (`UseXminAsConcurrencyToken()`).
- **Conflict Handling:** Catch `DbUpdateConcurrencyException` and return HTTP 409 (RFC 7807) with actionable error details in Spanish.
- **Stock Integrity:** Enforce `CHECK ("StockQuantity" >= 0)` in database. Only products with `StockQuantity > 0` may be fetched for sale. Never sell quantities exceeding stock.

## 5. API CONTRACTS & ERROR HANDLING
- **Strict RFC 7807:** Zero plain text or empty HTTP errors. All non-2xx responses must return standard `ProblemDetails`.
- **OpenAPI / Single Source of Truth:** No anonymous objects. All endpoints must return explicit typed DTOs.
- **Client Generation:** Frontend must consume APIs exclusively via Orval autogenerated hooks (`npm run api:generate`). Manual `fetch` or `axios` is prohibited. Never mutate generated files.

## 6. FRONTEND RULES & PATTERNS
- **Zero `useEffect` for Data:** Prohibited to sync SWR cache into local `useState`. Derive state directly or compute in render.
- **Forms & Validation:** `react-hook-form` paired strictly with `zod` inferred types (`useForm<z.infer<typeof schema>>`). No blind type assertions (`as any`, `!`).
- **Microinteractions:** All interactive elements must include `cursor-pointer`. Disabled elements must enforce `disabled:cursor-not-allowed disabled:opacity-50`.

## 7. SCOPE BOUNDARIES (4 VIEWS ONLY)
The frontend is strictly limited to 4 interfaces:
1. Point of Sale (Master-Detail): customer header, item table, tax summary, action buttons.
2. Smart Customer Search Modal: paginated, multi-field search, debounced.
3. Smart Product Search Modal: paginated, multi-field search, stock filter (`> 0`), debounced.
4. Invoice Lookup & Viewer: smart search by invoice number/customer, detail view, PDF preview/download.
